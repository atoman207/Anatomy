LABNOTE マーケティングサイト構成案

1. この資料の目的

LABNOTEを初めて知る研究者・研究室責任者・大学や研究機関の担当者に対し、次の5点を短時間で理解してもらい、無料登録または問い合わせにつなげるためのサイト構成を定義する。

  1. どのような課題を解決するサービスか
  2. 誰のためのサービスか
  3. どのような仕組みで解決するか
  4. 競合や既存の作業方法と何が違うか
  5. どのような料金で利用できるか

この資料は、現行実装を根拠にしたマーケティング設計である。未実装の機能を実装済みのように訴求しない。

2. サービスの基本定義

一言で表すと

話すだけで実験記録を残し、データ整理・統計解析・論文検索・AI査読までを一つにつなぐ研究支援プラットフォーム。

解決する課題

研究現場では、実験そのもの以外の作業に多くの時間がかかっている。

  • 実験中に手が離せず、ノートを後から書くため記録漏れや記憶違いが起こる
  • 試薬、Lot番号、実験条件、解析結果、参考文献が別々の場所に保存される
  • 測定機器から出力されたファイル名やサンプル情報の整理が属人的になる
  • 統計解析や論文用図版の作成に専門知識と手間が必要になる
  • 投稿前の論文評価には複数分野の専門知識と多くの時間が必要になる
  • 研究記録が後から編集されていないことや、誰が何をしたかを説明しにくい
  • 研究室内でデータ、実験、メンバー、権限を一元管理しにくい

提供価値

LABNOTEは研究の流れを分断せず、次の一連の作業を一つのサービス内で完結させる。

  1. 実験と試薬・Lotを選択
  2. テンプレートを選択または作成
  3. 実験内容を音声またはテキストで記録
  4. AIで記録を構造化し、図版も作成
  5. PubMed・Crossrefから関連論文を検索
  6. 実験レポートをPDFで保存
  7. データ整理、統計解析、論文用図版作成
  8. 3名のAI査読者による投稿前レビュー
  9. 研究室単位の共有、権限管理、監査ログ保存

3. 想定顧客

主要顧客

大学院生

  • 実験記録や解析に不慣れで、作業手順を標準化したい
  • 修士論文・博士論文に向けて記録と文献を整理したい
  • 指導教員に説明できる形で実験履歴を残したい

刺さる訴求: 「実験台で話した内容が、そのまま提出可能な記録になる」

ポスドク・個人研究者

  • 複数プロジェクトを並行し、記録・解析・論文執筆の時間を短縮したい
  • 投稿前に方法、統計、新規性、論理構成を確認したい

刺さる訴求: 「記録から投稿前チェックまで、一人の研究をAIが支える」

企業研究者

  • 再現性、証跡、監査対応を重視している
  • ファイル命名やサンプル情報を標準化したい
  • チームで同じ形式の記録を運用したい

刺さる訴求: 「速く記録し、後から説明できる研究データへ」

大学研究室・PI・研究室管理者

  • メンバーごとに記録形式が異なる
  • 実験・試薬・データ・ノートの所在を一元化したい
  • メンバーと権限を研究室単位で管理したい

刺さる訴求: 「研究室全体の実験記録を、同じ流れと同じ基準で管理」

大学・研究機関

  • 複数研究室を横断して管理したい
  • 研究公正、監査、記録の追跡可能性を高めたい
  • 導入支援や組織向けサポートが必要

刺さる訴求: 「複数研究室の記録基盤と監査証跡を一つに」

4. 競合・既存手段との差別化

比較対象

  • 紙の実験ノート
  • Word、Excel、共有フォルダ
  • 一般的な電子実験ノート（ELN）
  • 単体の統計解析ソフト
  • 単体の論文検索・AI査読サービス

LABNOTEの違い

1. 実験ノートだけで終わらない

一般的な電子実験ノートが記録・保存を中心とするのに対し、LABNOTEは、試薬管理、音声入力、データ整理、統計解析、論文検索、PDFレポート、AI査読までをつなげる。

2. 研究の順序に沿った5ステップ

実験選択、試薬・Lot、テンプレート、実験ノート、論文検索を一つのウィザードとして進められる。個別機能の寄せ集めではなく、実際の研究作業に沿った導線を持つ。

3. 音声記録と確認可能なAI処理

話した内容を文字起こしし、研究者が確認してから構造化する。AIが未入力情報を推測で埋めるのではなく、不足項目を「未記録」として扱う設計である。

4. 検索結果の実在性を重視

AIに参考文献そのものを生成させず、AIが検索式を作り、PubMedとCrossrefから実在する文献を取得する。

5. 3つの観点によるAI査読

方法・統計、研究内容・新規性、論文構成・論理を、それぞれ独立したAI査読者が評価する。一つの総合コメントだけではなく、弱点を観点別に確認できる。

6. 「後から説明できる」記録

研究室単位の権限管理、変更制限、追記型の監査ログによって、誰が・いつ・何をしたかを追跡できる。

推奨ポジショニング

電子実験ノートではなく、記録から論文投稿までをつなぐ研究ワークフロー基盤

価格だけで一般的なELNと競争するのではなく、「記録後の整理・解析・検索・査読まで含む」ことを中心に差別化する。

6. 推奨するトップページ構成

現行トップページは「ヒーロー → お知らせ → サービス説明 → 機能 → AI画像生成 → 記録の信頼性 → ダッシュボード → 料金」という順序である。機能説明は豊富だが、顧客の課題、対象者、競合との違い、全プラン料金が一画面で理解しにくい。

2. ファーストビュー

目的: 3秒以内に「誰の、何を、どう変えるサービスか」を伝える。

推奨コピー:

補足コピー:

3. 課題提起

見出し例: 「研究時間が、記録と整理で失われていませんか？」

4つの代表課題をカードで示す。

  1. 実験後のノート作成に時間がかかる
  2. 試薬・データ・参考文献が分散する
  3. 解析と図版作成が属人化する
  4. 投稿前の確認に専門知識と時間が必要

最後に「LABNOTEなら、これらを一つの研究フローとして扱えます」と解決策へ接続する。

4. 解決方法・3ステップ

見出し例: 「記録する。整理する。投稿に備える。」

STEP 1: 話して記録

実験内容を音声入力し、試薬・Lotやテンプレートと結び付ける。

STEP 2: 整理・解析・保存

ファイルとサンプル情報を整理し、統計解析・図版作成を行い、PDFレポートとして保存する。

STEP 3: 調べて査読

関連文献を検索し、3名のAI査読者が投稿前の原稿を観点別に評価する。

8. 選ばれる理由

見出し例: 「一般的な電子実験ノートとの違い」

比較軸は次の5点に限定し、視認性を高める。

  • 音声からの実験記録
  • 記録からPDFまでの一連のウィザード
  • データ整理・統計解析・図版作成
  • 実在文献に基づく論文検索
  • 3観点のAI査読
  • 研究室権限と監査ログ

競合名を直接掲載する場合は、公開時点の各社仕様を調査し、根拠URLと確認日を社内で保存する。

9. 信頼性・セキュリティ

見出し例: 「研究記録だから、速さだけでなく説明可能性を」

訴求項目:

  • 研究室単位のデータ管理
  • ロールごとのアクセス制御
  • 確定記録の変更制限
  • 追記型の監査ログ
  • 統計処理と作図はブラウザ内で実行
  • AIが入力されていない実験条件を推測で補完しない
  • 文献はPubMed・Crossrefの実在データから取得

「完全に改ざん不可能」「データは一切外部送信されない」など、実装より強い断定表現は避ける。音声、質問、論文本文など、機能に応じて外部AIへ送信される情報があるため、プライバシーポリシーで明確に説明する。

10. 導入効果・実績

導入前は、実績がない状態で架空の数値や推薦コメントを掲載しない。

初期は次の情報で代替する。

  • 1回の実験記録が完成するまでのデモ時間
  • 音声入力からPDF生成までの画面
  • 対応している統計手法・出力形式
  • AI査読のサンプルレポート

利用者が増えた後は、同意を得て次を掲載する。

  • ノート作成時間の削減率
  • 記録漏れの減少
  • 月間作成レポート数
  • 継続利用率
  • 所属・実名掲載を許諾された顧客事例

  • 投稿前に確認すべき統計・方法・論理構成
  • AI査読を使うときに研究者が最終確認すべきこと
  • 研究室でファイル命名規則を統一する方法
  • PubMed検索式の作り方

記事末尾では、内容に応じて「無料で実験記録を試す」または「AI査読を試す」へ誘導する。

10. 表現ガイド

推奨する表現

  • 「AIが研究者の確認を支援する」
  • 「入力内容をもとに構造化する」
  • 「PubMed・Crossrefから実在する文献を取得する」
  • 「投稿前の弱点を観点別に確認する」
  • 「研究記録を後から説明しやすくする」

避ける表現

  • 「AIが正しい実験ノートを完全自動で作る」
  • 「査読に必ず通る」
  • 「研究不正を完全に防ぐ」
  • 「データは一切外部に送信されない」
  • 「どの競合よりも優れている」
  • 根拠のない削減率、導入社数、満足度

AIは補助であり、実験条件、統計結果、引用、査読結果の最終確認は研究者が行うことを明記する。

  • 記録ウィザード完了率
  • PDF生成率
  • 個人研究者・研究室プランへの転換率
